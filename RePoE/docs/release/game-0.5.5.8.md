# 0.5.5.8 game declaration

This declaration defines the ordinary international 0.5.5.8 upgrade from
`game/0.5.5.5-3`, published as `inputs/0.5.5.8-1` and `game/0.5.5.8-1` and
currently selected in `release/ci.json`.

The declaration uses the existing release builder, native exporters and
policy rebinder. No historical declaration, policy, source acceptance record,
producer identity or receipt is changed.

## Policies, carried members and display names

Fourteen new policies are generated by `policy:rebind` from
`release/0.5.5.5-3`. Their changes are the actual manifest/payload identities
and target patch; existing codec and review decisions stay intact. No
holdout, synthetic closure, new column allowance or frame decision is used.
Forward mode retains the complete coverage report and the normal D40
publication predicate.

The reference and frozen source are the published `game/0.5.5.5-3`.
All 26 frozen members retain exact source bytes, reasons and exit criteria.
Each new frozen declaration entry records its source member, patch and tag
in `carried_from`. Moving those bytes under the new target prefix does not
declare that their contents were exported from 0.5.5.8. The existing legacy
0.5.5.4.2 package and tree compatibility label `0_5` remain pinned.

The optional `item-class-names` job reads this declaration's real 0.5.5.8
facts and registers `overlay/item_class_names.json` in the snapshot.
The observed table has 118 rows and 93 nonempty names; those are results
from this input, not acceptance thresholds copied from an older package.
The English text table equals the facts table, and Traditional Chinese has
the same stable ItemClasses Id set. Language adoption and translation
matching remain the locale owner's responsibility.

Formal inclusion of this optional member requires the corresponding PoBR data
contract increment. No adapter Rust dependency change is required (`contract/1.4`
was noted during preparation as the next increment).

## Publication status

`inputs/0.5.5.8-1` and `game/0.5.5.8-1` are published, `release/ci.json` selects
`0.5.5.8` as `current`, and PoBR adopts this release in `pipeline/data.lock.json`.
Because `release/0.5.5.8/inputs.lock.json` is never rewritten after preparation,
the lock retains its declaration-time `"publication": "pending"` and
`"publication_status": "pending"` fields as frozen input metadata (while the
crafting lock keeps its validator-required `"publication": "published"` reader
field).
