# 宝石品质：基于当前事实的发布范围

当前使用 [`0.5.5.5-publication-policy.json`](0.5.5.5-publication-policy.json)（v2）。
adapter 从六张已认证的物理表核对完整品质 owner 与宝石关系：429 个原始 owner 中发布 424 个，
仅排除五个全部关联宝石均标记 `[DNT` 的 owner。主效果和附加效果关系都参与核对。
没有宝石关系、仅有 OLD/UNUSED 标记或同时关联真实宝石的 owner 不能被排除。

政策仍列出完整启用／排除清单，但每个决定都由当前原始事实验证。
历史 PoB 模板成员不再决定发布资格；新增的 14 个 owner 保留真实来源的全部品质属性、数值与作用域。
原来的 [`0.5.5.5-facts-policy.json`](0.5.5.5-facts-policy.json) 不变，供历史 410/19 产物精确重放。

属性通过物理 `_row` 外键连接稳定 ID。主／附加品质依原顺序保留，带符号 permille 除以 1000，
零值、负值、重复属性和原生作用域数组均不改写。Snipe 的 `[1,2,3]` 原样保留；
越界位置 3 由消费者诊断，不重排或虚构分支。排除项仍保留原始值、理由和具体宝石关系证据。

`reference` 与 vendor 摘要仅是历史迁移证据。发布完整性不代表所有机制已被引擎支持；
品质计算与作用域解释仍由 PoBR 负责。现有 JSON metadata 已兼容其 typed reader，无需升级依赖。
命令、输入 pin、收据、历史重放和测试范围见 [ordinary quality](../../ordinary-quality.md)。

更新来源时新建固定政策，核对所有 owner、主／附加向量与关系，输出到新的 `.cache/`，
再准备不可变完整游戏包。owner 发布、PoBR 更新数据锁与活动数据采用是独立步骤。
